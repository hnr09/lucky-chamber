# Lucky Chamber (가제)

샷건 룰렛 심리전 + 로그라이크 덱빌딩 점수 공식 + 슬롯머신 도박을 섞은 웹게임.
지금은 **기초 단계**: 규칙 엔진, 테스트, 플레이 가능한 최소 UI.

## 실행

```bash
npm run dev      # http://localhost:5173  (ES 모듈이라 file:// 로는 안 열림)
npm test         # 엔진 단위 테스트 + 무작위 3000판 시뮬레이션
```

`?seed=1234`를 붙이면 같은 판을 재현할 수 있다. `?fast`를 붙이면 연출을 건너뛴다.

처음 실행하면 **📖 설명서**가 열린다(하단 버튼으로 다시 보기).

**조작**: PC는 **마우스로 바라보는 대상을 클릭해서 쏜다**(아래를 내려다보면 나). 휴대폰은 버튼.
혼자 하기: 테이블 위 칩을 눌러 최대 3개까지 베팅(키보드 1~9, 다시 누르면 취소) → 딜러를 쏜다(D) / 나를 쏜다(S).

**그래픽**: Three.js(CDN, 0.170.0)로 그린 로우폴리 3D. 저해상도로 렌더링한 뒤 픽셀 그대로
확대해서 레트로 느낌을 낸다(`scene3d.js`의 `PIXEL_SCALE`). 부적은 테이블 위 패로 서 있고,
전화가 오면 일어나서 왼쪽 벽 전화기로, 상점은 오른쪽 진열장으로 카메라가 이동한다.
HUD와 상점 메뉴는 HTML 오버레이.

## 핵심 루프

1. **결투**: 약실에 실탄/공포탄이 섞여 장전된다(개수만 공개, 순서는 비공개).
   - 딜러를 쏜다 → 실탄이면 딜러 체력 -1, **판돈 × 배수** 만큼 득점. 턴이 넘어간다.
   - 나를 쏜다 → 공포탄이면 **배수 +1**, 턴 유지 (점수는 없음). 실탄이면 체력 -1.
   - **점수는 딜러를 실탄으로 맞혔을 때만** 들어온다. 화면에 남은 탄과 실탄 확률, 추천 행동이 나온다.
   - 재장전 시 배수는 1로 초기화되고 아이템 1개가 보급된다.
2. **할당량 (약실 3개 마감)**: 스테이지마다 약실 3개 안에 할당량을 채워야 한다.
   - 할당량 전에는 딜러가 죽지 않고 체력 1로 버틴다.
   - 할당량을 채우면 **💰 정산하고 일어서기**로 즉시 클리어. 더 버티면 초과 보너스 코인(할당량 2배마다 +3), 딜러를 쓰러뜨리면 처치 보너스 +2.
   - 약실이 다 떨어졌을 때 할당량 미달이면 게임 오버.
   - 체력은 스테이지마다 전부 회복. 스테이지가 오를수록 딜러가 실탄을 더 넣고, 약실을 들여다보고, 2배 피해탄을 쓴다.
   - 클리어 보상: 코인 + **티켓** + 화이트 칩 2개.
3. **전화**: 클리어하면 전화가 울리고 **증강** 3개 중 하나를 고른다 (런 내내 영구).
4. **상점**: 부적, 아이템, **베팅 칩**, 칩 제거, **티켓 부스**(희귀 부적·영구 강화), 슬롯머신.
5. 8스테이지 돌파 시 승리.

### 베팅 칩
칩 주머니(덱)에서 손패 5개를 뽑는다. 한 번 쏠 때 **최대 3개까지 동시에** 걸 수 있고(고른 순서대로 발동),
3·6스테이지 클리어와 증강 '세 번째 손'으로 거는 칸이 1개씩 늘어난다. 칩마다 **베팅 배당**(판돈 +N / 배수 +N / 배수 ×N)과
**고유 능력**이 있다. 건 칩은 그 사격에만 적용되고,
다 쓴 칩은 버린 더미로 간다. 주머니가 비면 버린 더미를 섞어서 다시 뽑는다.
발동 순서: **건 칩(배당 → 능력) → 부적(테이블 왼쪽부터)**. 게임 화면의 📋 배당표에서 내 칩들의 수치를 볼 수 있다. 점수 = **판돈 × 배수**. 배수는 나를 쏴서 공포탄이 나올 때마다 +1 쌓이고 재장전하면 1로 돌아간다.

## 구조

```
src/core/          DOM을 모르는 순수 로직 (Node에서 그대로 테스트)
  config.js        밸런스 수치 전부
  rng.js           시드 고정 난수 (상태 = { s } 하나 → 세이브/리플레이 쉬움)
  engine.js        newRun(), act(state, action) → events[]
  charms.js        부적 정의 (희귀 부적 포함)
  chips.js         베팅 칩 정의, 칩 주머니
  hooks.js         효과 발동 순서 (건 칩 → 부적)
  augments.js      전화 증강
  tickets.js       티켓 부스
  versus.js        1:1 결투 규칙
  online.js        온라인 결투 동기화 (방장이 진행, 연결 방식과 무관)
  items.js         소모품 정의
  shop.js          상점 행동
  reels.js         슬롯머신
  dealer.js        딜러 AI
  chamber.js       약실 장전
src/ui/            엔진 이벤트를 받아서 그리기만 함
  main.js          컨트롤러 + HUD
  scene3d.js       3D 테이블 씬 (딜러, 총, 탄, 칩, 점수 모니터, 연출)
  panels.js        상점 / 전화 / 종료 오버레이
  versus-ui.js     홈 화면 + 1:1 결투 화면
  net-peer.js      온라인 연결 (PeerJS P2P)
tests/             node:test
```

**원칙**: UI는 `act()`만 호출하고 상태를 직접 바꾸지 않는다. 엔진은 무슨 일이 일어났는지
이벤트 배열로 돌려주고, UI는 그걸로 연출과 로그를 만든다. 나중에 렌더러를 Canvas나
PixiJS로 바꿔도 엔진은 그대로 쓴다.

## 모드

홈 화면에서 고른다.

- **혼자 하기**: 딜러와 8스테이지 로그라이크 (위 규칙).
- **같이 하기 (2~4명)**: 한 기기에서 번갈아 쏘는 결투. 마지막 생존자가 판 승리, 2판 먼저 이기면 승리. 체력 4, 배수 3 이상에서 맞히면 피해 2.
- **온라인 대전 (최대 4명)**: 방을 만들면 5자리 코드가 나온다. 친구들이 그 코드(또는 `?join=코드` 초대 링크)로 들어오면 방장이 시작.
  - WebRTC P2P([PeerJS](https://peerjs.com) 1.5.4, CDN). 서로를 찾을 때만 PeerJS 공개 중계 서버를 쓰고,
    게임 데이터는 두 브라우저가 직접 주고받는다. **별도 서버나 키가 필요 없다.**
  - 방장이 게임을 진행하고(`src/core/online.js`), 참가자 화면에는 탄 순서가 가지 않는다.
  - 일부 회사·학교 네트워크처럼 P2P 연결을 막는 곳에서는 접속이 안 될 수 있다.

## 사운드

효과음은 [plinkfx](https://github.com/maximilianfeix/plinkfx)(CC0, 코드로 합성되는 효과음)를
`src/vendor/plinkfx/`에 그대로 넣어 쓴다. 이벤트별 매핑은 `src/ui/audio.js`.
하단 🔊 버튼으로 끌 수 있고 설정은 브라우저에 저장된다.

## 밸런스

```bash
npm run balance -- 3000 0.55   # 판수, 봇의 자기 사격 기준(실탄 확률)
```

`sim/bot.js`의 전략 봇(남은 탄 계산, 최고 칩 조합, 우선순위 쇼핑)으로 여러 판을 돌려
스테이지별 사망률·할당량 실패율·점수 배율을 출력한다. 현재 목표치:
봇 승률 약 15% (사람은 조합을 더 잘 짜므로 더 높다), 사망과 할당량 실패가 비슷한 비중,
스테이지가 오를수록 둘 다 증가. 위험을 더 감수할수록 승률이 오르되 사망도 늘어난다.

## 콘텐츠 추가하기

- **부적**: `charms.js`의 `CHARMS`에 항목 추가. 훅(`onScore`, `onHeatGain`,
  `onIncomingDamage`, `onStageEnd`, `onSpin`)에서 `ctx`를 수정하고 라벨 문자열을 반환.
- **베팅 칩**: `chips.js`의 `CHIPS`에 추가. 부적 훅 + `onShotEnd`(코인, 파괴, 손패 복귀).
- **증강**: `augments.js`의 `AUGMENTS`에 `apply(state, rng)` 추가.
- **아이템**: `items.js`에 정의를 추가하고 `engine.js`의 `useItem`에 효과를 넣는다.
- **밸런스**: `config.js`의 `CONFIG`, `QUOTAS`, `stageSpec`.
