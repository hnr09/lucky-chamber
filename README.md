# Lucky Chamber (가제)

샷건 룰렛 심리전 + 로그라이크 덱빌딩 점수 공식 + 슬롯머신 도박을 섞은 웹게임.
지금은 **기초 단계**: 규칙 엔진, 테스트, 플레이 가능한 최소 UI.

## 실행

```bash
npm run dev      # http://localhost:5173  (ES 모듈이라 file:// 로는 안 열림)
npm test         # 엔진 단위 테스트 + 무작위 3000판 시뮬레이션
```

`?seed=1234`를 붙이면 같은 판을 재현할 수 있다.

## 핵심 루프

1. **결투**: 약실에 실탄/공포탄이 섞여 장전된다(개수만 공개, 순서는 비공개).
   - 딜러를 쏜다 → 실탄이면 딜러 체력 -1, **칩 × 열기** 만큼 득점. 턴이 넘어간다.
   - 나를 쏜다 → 공포탄이면 **열기(배수) +1**, 소량 득점, 턴 유지. 실탄이면 체력 -1.
   - 재장전 시 열기는 1로 초기화되고 아이템 1개가 보급된다.
2. **할당량**: 딜러를 쓰러뜨린 순간 점수가 할당량 이상이어야 통과, 미달이면 게임 오버.
   그래서 일찍 죽이면 오히려 손해다. 위험을 감수하고 열기를 쌓아야 한다.
3. **상점**: 부적(패시브), 아이템(소모품), 슬롯머신, 새로고침, 부적 판매·순서 변경.
4. 8스테이지 돌파 시 승리.

## 구조

```
src/core/          DOM을 모르는 순수 로직 (Node에서 그대로 테스트)
  config.js        밸런스 수치 전부
  rng.js           시드 고정 난수 (상태 = { s } 하나 → 세이브/리플레이 쉬움)
  engine.js        newRun(), act(state, action) → events[]
  charms.js        부적 정의 + 훅 시스템 (슬롯 순서대로 발동)
  items.js         소모품 정의
  shop.js          상점 행동
  reels.js         슬롯머신
  dealer.js        딜러 AI
  chamber.js       약실 장전
src/ui/            엔진 이벤트를 받아서 그리기만 함
tests/             node:test
```

**원칙**: UI는 `act()`만 호출하고 상태를 직접 바꾸지 않는다. 엔진은 무슨 일이 일어났는지
이벤트 배열로 돌려주고, UI는 그걸로 연출과 로그를 만든다. 나중에 렌더러를 Canvas나
PixiJS로 바꿔도 엔진은 그대로 쓴다.

## 콘텐츠 추가하기

- **부적**: `charms.js`의 `CHARMS`에 항목 추가. 훅(`onScore`, `onHeatGain`,
  `onIncomingDamage`, `onStageEnd`, `onSpin`)에서 `ctx`를 수정하고 라벨 문자열을 반환.
- **아이템**: `items.js`에 정의를 추가하고 `engine.js`의 `useItem`에 효과를 넣는다.
- **밸런스**: `config.js`의 `CONFIG`, `QUOTAS`, `stageSpec`.
